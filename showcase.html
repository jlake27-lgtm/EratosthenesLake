01 · The question

Can you measure the whole planet without leaving your desk?

Eratosthenes' idea: the Sun is so far away that its rays arrive parallel. If two places on the same meridian see the noon Sun at different heights, that difference in angle is the slice of the Earth's 360° that lies between them.

In class this is a Stellarium exercise: look up the Sun's altitude at noon in two cities, convert degrees–minutes–seconds to decimals, subtract, measure the distance, and set up a proportion. EratosthenesLake does "the same steps as the Stellarium classroom exercise, done automatically and shown as a worksheet" — for any pair of ~34,600 places, on any date.

What the site does for you

  1. ACity search across Stellarium's own location database, so any pair can be cross-checked in Stellarium.
  2. BPartner suggestions within ±0.5–3° of longitude of City A, filtered by population and time zone.
  3. CSun at the meridian: solar-noon time, altitude (DMS and decimal), azimuth, with Stellarium's atmosphere toggle.
  4. DWorksheet for handout steps 9–11, with % error against 40,075 km and 40,008 km.
  5. EWarnings for pairs off the meridian, too close, in different time zones, on opposite sides of the Sun, or in polar night.
  6. FMap and accuracy charts: your own trials plus two reference charts of 250 real city pairs each.
02 · How it works

Four steps from sunlight to kilometres

Every result follows the same path through measure() in src/experiment.js. Numbers below are the Boston → Maracaibo example.

Find solar noon

For each city, Astronomy Engine searches for the moment the Sun crosses the local meridian (hour angle 0) on the chosen local date and returns its altitude h and azimuth. Refraction is on by default, like Stellarium with the atmosphere shown.

Boston: h = 45.0553° at 16:34:29 UTC, due south

Turn altitude into a signed zenith angle

z = ±(90° − h)

Use + when the noon Sun is due south, − when it is due north. The sign records which way you face to see the Sun. That keeps the next step right even when the cities are in different hemispheres.

Get the arc angle

θ = |z_A − z_B|

With the Sun on the same side for both cities this equals the difference of altitudes. On opposite sides it becomes their sum.

Measure and set up the proportion

360° / θ = C / d → C = 360° × d / θ

GeographicLib measures d on the WGS84 ellipsoid. The default is the north–south distance between the two latitudes, which is what the Sun angle actually measures.

Why a few tenths of a percent under 40,075 km? The Earth is slightly flattened: its circumference through the poles is 40,008 km, and a degree of latitude is a little longer near the poles than near the equator (README).

03 · The geometry

Parallel rays, two zenith lines, one slice of Earth

The Sun's rays reach both cities parallel. Each city's "straight up" direction points away from the Earth's centre, so the angle between a city's zenith and the Sun equals its zenith angle z. The two radii meet at the centre with angle θ — the same θ the worksheet gets by subtracting zenith angles.

06 · Code highlights

Three small ideas that make it work

Signed zenith angles

Subtracting altitudes breaks when the noon Sun is south of one city and north of the other. Giving each zenith angle a sign from the Sun's azimuth makes one formula, |zA − zB|, correct in every case — the cross-hemisphere test pair depends on it.

src/calc.jslines 37–52
export function signedZenith(altitude, azimuth) {
  const facingSouth = Math.cos((azimuth * Math.PI) / 180) < 0;
  return (facingSouth ? 1 : -1) * (90 - altitude);
}

/** Step 10: angle of the arc of the Earth between the two cities. */
export function arcAngle(sunA, sunB) {
  const zA = signedZenith(sunA.altitude, sunA.azimuth);
  const zB = signedZenith(sunB.altitude, sunB.azimuth);
  return {
    zA,
    zB,
    sameSide: Math.sign(zA) === Math.sign(zB) || zA === 0 || zB === 0,
    angle: Math.abs(zA - zB),
  };
}

Solar noon without time-zone rules

The search starts at local mean midnight — UTC midnight shifted by longitude — so it always lands on the right local day, even near the date line (the Auckland test checks this). Then Astronomy Engine finds hour angle 0 and applies refraction if asked.

src/sun.jslines 16–25
  // Start the search at local *mean* midnight (UTC midnight shifted by longitude).
  // Solar noon is always within ~20 min of 12h later, so this finds the transit
  // on the right local day without needing time-zone rules.
  const [y, m, d] = isoDate.split('-').map(Number);
  const localMidnightUtc = Date.UTC(y, m - 1, d) - (place.lon / 15) * 3600_000;
  const start = Astronomy.MakeTime(new Date(localMidnightUtc));

  const event = Astronomy.SearchHourAngle(Astronomy.Body.Sun, observer, 0, start, +1);
  const eq = Astronomy.Equator(Astronomy.Body.Sun, event.time, observer, true, true);
  const hor = Astronomy.Horizon(event.time, observer, eq.ra, eq.dec, refraction ? 'normal' : undefined);

The north–south distance trick

The Sun angle only measures how far apart the cities are in latitude. Moving both cities onto longitude 0 before asking GeographicLib for the distance gives exactly that meridian arc on the WGS84 ellipsoid, next to the ordinary straight-line distance.

src/geo.jslines 22–31
export function cityDistances(a, b) {
  const straight = WGS84.Inverse(a.lat, a.lon, b.lat, b.lon);
  const meridian = WGS84.Inverse(a.lat, 0, b.lat, 0);
  return {
    straightKm: straight.s12 / 1000,
    northSouthKm: meridian.s12 / 1000,
    dLat: b.lat - a.lat,
    dLon: lonDiff(a.lon, b.lon),
  };
}
07 · Tech stack

What it's built with

Language & tooling

JavaScript ES modules

All app logic, in ten modules under src/, plus HTML and CSS.

Vite ^8.3.1

Dev server and static build; base: './' so the site works from a GitHub Pages sub-path.

Vitest ^5.0.2

Runs the 11 math tests in test/math.test.js.

Node.js ≥ 22.12

Required to run it; also runs scripts/build-cities.mjs to convert Stellarium's data.

GitHub Actions + Pages

Every push to main tests, builds and publishes dist/. If tests fail, nothing is deployed.

Libraries

Astronomy Engine ^2.1.19

Finds the Sun's meridian transit and its altitude/azimuth, with optional refraction.

GeographicLib ^2.2.0

Geodesic distances on the WGS84 ellipsoid, both straight-line and north–south.

Leaflet ^1.9.4

Map of the two cities and City A's meridian, on OpenStreetMap tiles.

Hand-built SVG charts

src/chart.js is a dependency-free scatter chart for trials and reference pairs.

Data

Stellarium locations

base_locations.txt and regions-geoscheme.tab (GPL-2.0+), city data originally from GeoNames (CC-BY 4.0).

IBM Plex Sans & Mono

The app's typefaces, via Google Fonts.

09 · Limitations & what's next

Honest edges

The repo has no TODOs or roadmap. These are limits stated in the README or visible in the code.

Needs a web server

Opening the app's index.html straight from disk doesn't work, because browsers block module scripts on file:// pages. Use npm run dev or the live site.

README.md · src/main.js

A spherical proportion

C = 360 × d / θ assumes a sphere. Because the Earth is flattened, even the north–south method usually lands a few tenths of a percent below 40,075 km.

README.md "How the calculation works"

Time zones checked for today

"Same time zone" compares UTC offsets right now, not on the chosen date, so daylight-saving differences on other dates aren't considered.
