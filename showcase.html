01
Browser app · Eratosthenes' method

EratosthenesLake

Pick two cities roughly north–south of each other. It finds the noon Sun's height in each, measures the distance between them, and works out the size of the planet.

Try the demo Open the full site ↗
How it works
  1. 1Find solar noonAstronomy Engine gives the Sun's altitude h in each city.
  2. 2Signed zenith anglez = ±(90° − h)
  3. 3Arc between the citiesθ = |z_A − z_B|
  4. 4ProportionC = 360° × d / θ

src/calc.js
export function signedZenith(altitude, azimuth) {
  const facingSouth = Math.cos((azimuth * Math.PI) / 180) < 0;
  return (facingSouth ? 1 : -1) * (90 - altitude);
}

export function arcAngle(sunA, sunB) {
  const zA = signedZenith(sunA.altitude, sunA.azimuth);
  const zB = signedZenith(sunB.altitude, sunB.azimuth);
  return { zA, zB, angle: Math.abs(zA - zB) };
}

One formula that still works when the cities are in different hemispheres.

src/sun.js
// Start the search at local *mean* midnight (UTC midnight shifted by longitude).
const localMidnightUtc = Date.UTC(y, m - 1, d) - (place.lon / 15) * 3600_000;
const start = Astronomy.MakeTime(new Date(localMidnightUtc));

const event = Astronomy.SearchHourAngle(Astronomy.Body.Sun, observer, 0, start, +1);

Always lands on the right local day, even near the date line.

src/geo.js
export function cityDistances(a, b) {
  const straight = WGS84.Inverse(a.lat, a.lon, b.lat, b.lon);
  const meridian = WGS84.Inverse(a.lat, 0, b.lat, 0);
  return { straightKm: straight.s12 / 1000, northSouthKm: meridian.s12 / 1000 };
}

Moving both cities to longitude 0 measures only the north–south arc, which is what the Sun angle sees.

    Inside ai-detector

    src/ai_detector/binoculars.py
    for start in range(0, len(all_token_ids), _WINDOW_TOKENS):
    window = all_token_ids[start : start + _WINDOW_TOKENS]
    window_nlls, window_ces = _score_window(window, observer, performer, device)
    total_nll += sum(window_nlls)
    total_ce += sum(window_ces)
    total_tokens += len(window_nlls)

binoculars_score = (total_nll / total_tokens) / (total_ce / total_tokens)

    Adds up all the windows first and divides once at the end. Averaging each window's ratio would skew the result.

    src/ai_detector/scoring.py
    total_weight = sum(config.SCORING_WEIGHTS[name] for name in per_feature)

for name, (value, ai_end, human_end) in per_feature.items():
    weight = config.SCORING_WEIGHTS[name] / total_weight
    ai_likelihood = _linear_score(value, ai_end, human_end)
    total += weight * ai_likelihood

    A missing signal is left out of the average. It isn't counted as a zero.

    Limits
    • A small test set (16 samples), mostly old public-domain text on the human side.
    • The AI samples are almost all from Claude, so the thresholds lean toward Claude's style.
    • Short or plainly worded AI text often still scores as human. Treat the score as a hint, not a verdict.
